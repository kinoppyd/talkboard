# 実装の構造とPoCの制約

## USB側とPicoRuby側

core1がPIO USB Hostを処理し、core0の既存USB pumpが標準USB Deviceを処理します。Host callbackは受信reportを固定長の構造へ変換します。Ruby VMはUSB callbackから呼びません。core0のRubyがI²CやGCで遅れても、割り込み側のUSB処理を継続する構造です。実機での遅延保証ではありません。

転送リングは32状態。押下・解放を最新状態だけにまとめず順に保持し、Device endpointが準備できるまで再試行します。各下流interfaceの受信は別々に登録し、idleなメディアendpointが通常キーを止めないようにしています。各未完了受信に転送リングの空き1件を予約します。転送リング自体が埋まると受信再登録を抑えますが、キーボード内部の有限バッファまで無損失とは保証できません。

観測リングは128イベント。キー状態の差分から新規押下だけを取り出し、[時刻ms、Usage、修飾キー、欠落世代]をRubyへ渡します。同じ状態の繰り返しでは発話を増やしません。観測側が満杯でもUSB転送を止めず、世代番号で不連続を知らせます。

## 固定descriptorと入力範囲

- 通常keyboard: Usage 0〜255の32バイトbitmap。修飾キーは224〜231。Boot protocol時は8バイト・6KROへ変換し、6キー超はrolloverを返す。
- Consumer: 最大8個の16bit Usage（0〜1023）を配列として送信。
- System: Usage 0x81〜0x88をbitmapで送信。
- PCへのインターフェース構成は既存R2P2を基にCDC×3、HID×3。キーボードはHID0、Consumer/SystemはHID2。HID1のmouse descriptorは残るが、本PoCはマウスの入力中継を未実装。
- Report IDを含め64バイト以内の受信が基本。descriptorは最大1024バイト、解析は48フィールド・8 report・明示Usageリスト32個に制限。
- 下流は1 USB device、最大4 HID interface。内蔵ハブ・無線複合レシーバ等は未対応。キーボード機種未定のため実機互換性は未確認。

標準的なKeyboard配列・bitmap、Consumer配列・bitmap、Systemキー、LED Outputを扱います。HID long item、複雑なdelimiter、ベンダー独自データ等に対する汎用解釈器ではありません。対象機種のdescriptorで範囲を確認し、必要ならフィールド対応を拡張します。descriptorの形式が対応範囲外の場合や不正なreportは、転送に使わずエラー数を増やします。

Lock LEDはPCのOutput値を下流のLED Usageへ再配置し、Control SET_REPORTで送信します。各interfaceで最初に見つけたLED Output reportを扱うPoC実装です。複数のLED reportを使う特殊構成は未対応です。GET_REPORT、keyboard SET_IDLE、Boot/Report切り替えも処理します。VIA等のFeatureは中継しません。

USB接続を二つ終端するため、元機種のUSB識別情報や通信バイトをそのまま保存するものではありません。VID/PIDはR2P2由来の開発用値を引き継ぐため、製品として配布する場合は正当な識別情報を別途取得・設定してください。

## ローマ字の処理

US配列の英字を小文字に正規化し、解釈可能な音節から逐次キューへ入れます。文章やEnterを待ちません。対応表は `Talkboard::Romaji` 内にあり、主要な清音・濁音・半濁音・拗音、shi/chi/tsu/fu/ji等の別表記を処理します。

- 未確定末尾は50msだけ後続を待つ（PoCの仮設定）。nの後の母音、sh/ch/hy等を継続して解析。
- nnは撥音として確定し、次の母音があれば後ろのnを次音節の開始にも利用する。`konnichiwa` は ko / nn / ni / ti / wa に分解。
- 重なった子音はxtuを次の音節と一緒に送る。単独の促音だけを先行送信しない。
- nだけのタイムアウトはnnとして確定。読めない子音だけの末尾は破棄。
- Backspace/Delete/矢印は編集として扱わず無視。Ctrl/Alt/GUI付き入力も読み上げから除外。PCにはこれらもそのまま中継。
- 長押しは最初の押下のみ。空白・句読点・Enterは区切りとして扱うが必須ではない。
- 50msを超えてゆっくり打つと読みが分かれる場合がある。自然な発音を再現する仕様ではない。

時刻は下流でreportを受けた時点を保存し、32bitミリ秒の周回にも対応します。Rubyに未処理イベントが残っている間は、現在時刻だけで末尾を先に期限切れにしません。観測欠落が判明すると未確定末尾をリセットし、欠落前後を一語に連結しません。

## 音声キューとIC

音声記号キューは2048バイト・256音節単位のどちらかに達したら満杯です。**新しい単位全体を捨てるdrop-new**を採用し、保持済み分は順番に送ります。空きができれば受付を再開します。破棄した本文の退避や履歴保存は行いません。

ICがreadyなら126バイト以内の音声記号に終端の句点を加え、CR付きで一括送信します。本文は最大127バイト、CRは別です。音節の途中で分割しません。送信成功後はキュー内の参照をすぐ解放し、発話中の本文は保持しません。ICから次のready応答が来るまで次の文は送りません。

状態問い合わせは10ms以上空けます。I²C転送のtimeoutは20ms、応答待ちは30秒で異常扱い。これは音声キューの滞留期限ではありません。通信異常時は音声workerだけを停止し、部分送信の再生重複を避けて自動再送しません。復帰は配線を確認したうえで装置を再起動します。ICの構文エラーは数えて次の入力を処理します。

Ruby文字列の参照解放は即時の物理RAM消去ではありません。GCまでの残留やIC内部バッファはあり得ますが、本文の永続ログは作りません。

## 起動と運用上の制約

UF2には専用mainを埋め込み、起動すると中継・読み上げを開始します。R2P2 shellや標準入力コンソールは起動しません。ファイルシステムへの設定・本文保存も行いません。

無線・PSGを組み込まず、core1はHost専用8KiBスタック。Rubyヒープは320KiB。flash更新・Machine.sleep・PSGなどを動作中に追加で呼び出す運用は対象外です。既存SDKのflash設定をそのまま使うため、Host稼働中にflash書き込みをしないことが前提です。

下流切断では押下状態を解放します。PCが未接続の間の入力は破棄し、再接続時に蓄積入力を注入しません。remote wakeup要求は実装していますが、Mac・キーボードの休止復帰は未検証です。下流への低電力制御と上流USB suspend電流適合は未実装で、製品仕様としてのUSB電源管理は達成していません。

過電流はU3で制限し、GP13のLowを検出するとGP12をLowにして下流電源を止めます。問題を取り除いた後に再起動してください。電源断・MCU停止時にキーボードが直結相当に動く物理バイパスはありません。
